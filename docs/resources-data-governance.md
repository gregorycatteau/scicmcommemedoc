# Gouvernance des donnees ressources

## Principe

Une ressource referencee n est pas automatiquement un partenaire.
Une ressource partenaire n est pas automatiquement recommandee.
Le statut de verification reste separe de toute relation commerciale, associative ou cooperative.

## Qui peut proposer

Tout visiteur peut proposer une ressource via l interface de contribution.
La proposition n est jamais publiee automatiquement.

## Qui valide

Une personne habilitee par M Comme Medoc doit verifier :

- l existence de la ressource ;
- la source ;
- les coordonnees ;
- les horaires si affiches ;
- les produits ou services annonces ;
- la date de verification.

## Sources acceptables

Sources possibles :

- site officiel de la structure ;
- page publique maintenue par la structure ;
- document public ;
- confirmation directe datee ;
- observation terrain documentee.

Une information orale non datee ne suffit pas pour une fiche verifiee.

## Revalidation

Les horaires, prix, disponibilites et modes de distribution expirent.
Frequence recommandee :

- horaires et disponibilites : 3 a 6 mois ;
- existence et coordonnees : 6 a 12 mois ;
- fermeture : traitement prioritaire.

## Fermetures et litiges

Une fiche signalee comme fermee passe en verification.
En cas de litige, afficher un statut prudent ou retirer temporairement la fiche.

## Rectification et retrait

Une structure referencee peut demander :

- correction ;
- retrait ;
- clarification du statut ;
- suppression d une donnee de contact.

## Absence de favoritisme commercial

Les criteres d affichage doivent rester explicites :

- verification ;
- utilite territoriale ;
- pertinence pour la recherche ;
- fraicheur de l information.

La plateforme ne doit pas vendre une mise en avant commerciale sans le signaler clairement.

## Donnees de demonstration

Les donnees actuellement presentes dans `frontend/app/data/demoResources.ts` sont fictives.
Elles doivent etre remplacees par des donnees verifiees avant tout usage public comme repertoire local.
